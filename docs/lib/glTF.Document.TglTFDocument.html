glTF.Document

Declaration

type TglTFDocument = class(TObject)

Description

A glTF 2.0 document: its object tree and loading and saving.

Holds a TglTF object tree in Root, which is never nil. Loading replaces the tree only when the load succeeds, so a failed load leaves the previous asset in place. Saving never changes the tree: it works on a copy.

Not thread-safe; use an instance from one thread at a time. Every method blocks until it finishes, including the file reads and writes it does. 

Doc := TglTFDocument.CreateFromFile('model.gltf');
try
  Doc.SaveToFile('model.glb'); // every image inside the GLB
finally
  Doc.Free;
end;

Public procedure LoadFromFile(const AFileName: string);

Loads a .gltf or .glb file.

The format is detected from the content. External buffers and images are read relative to the file's folder, which becomes BaseDirectory. Missing external files do not fail the load: they are listed in Warnings and MissingResources. Errors in the JSON report their line, within the JSON chunk for a GLB.

When a referenced file is not found under its exact name, folder and file names are matched ignoring case, as glTF files made on Windows often differ in case from the files on case-sensitive file systems (Linux, Android, iOS).

Parameters
AFileName
The file to load.
Exceptions raised
EglTFParseError
The JSON is malformed or a value is invalid.
EglTFMissingPropertyError
A property the glTF schema requires is missing.
EglTFGLBError
The GLB container is invalid.
EFOpenError
The file cannot be opened.

Public procedure SaveToFile(const AFileName: string; const AOptions: TglTFSaveOptions); overload;

Saves as .gltf or .glb, chosen by the file extension.

The output is made file-complete. Every buffer and image stored as a separate file is written next to it, at the path its uri gives relative to the output, creating sub-folders as needed. A file whose data was not loaded is copied from where it was found, or from its original location. A file already there with the same bytes is left alone. SavedFiles lists what was done for each file. A file that cannot be found anywhere is written as a uri reference only, reported in SaveWarnings, and makes SaveComplete False.

An image saved as a separate file is not also kept in a buffer: when it was inside one, its bytes are cut out, the later data moves down and every bufferView index is renumbered. Files using Draco or meshopt compression are the exception, as those extensions refer to bufferViews in their own JSON; the bytes then stay and SaveWarnings says so. The document itself is never changed.

An image saved as a separate file is named, in order of preference: after its uri (keeping the uri's folders when they stay inside the output folder, otherwise only the file name); after its name, made safe for every platform's file system, with an extension from its MIME type; or <model>_image<N>. Names are unique within a save, ignoring case: images with identical bytes share one file, others get "_2", "_3" and so on before the extension. Buffer files follow the same rule, and nothing may take the name of the output file itself.

An image file never replaces a different file already on disk: it is renamed the same way instead. The exception is an image with TglTFImage.Shared set, whose file may be shared with other models: when it already exists it is used as it is, even if its bytes differ, and its uri may lead outside the output folder.

The separate files are written first and the main file last, so a failure leaves any existing main file untouched. Existing files of the same names are replaced.

Parameters
AFileName
The output file; its extension must be .gltf or .glb.
AOptions
Where buffer data goes and how the JSON is laid out.
Exceptions raised
EglTFError
The extension is not .gltf or .glb, the objects are not valid glTF, or a GLB's buffers[0] has no data.
EInOutError
A file cannot be written.

Public procedure SaveToStream(AStream: TStream; AFormat: TglTFFileFormat; const AOptions: TglTFSaveOptions); overload;

Saves to a stream in the given format.

A stream has no folder for separate files, so every buffer and image that has data is put inside it: in a GLB, buffers[0] goes into the BIN chunk; everything else becomes a data URI, or a buffer for images with Embed set. Only files that could not be found stay as uri references, which makes SaveComplete False.

Public function SearchMissingResources(const ADirectory: string; ARecursive: Boolean = True): Integer;

Looks for every missing file in a folder and loads those it finds.

For each missing file it tries, in order: the uri's relative path inside ADirectory, the file name directly in ADirectory, then (when ARecursive) the file name in any sub-folder. Names are compared ignoring case on every platform. A candidate that cannot be used, such as a buffer file that is too small, is skipped. Sub-folders that cannot be read are ignored.

Parameters
ADirectory
The folder to search.
ARecursive
Also search sub-folders; this can be slow on large folders.
Returns

How many missing files were found and loaded; 0 when ADirectory does not exist.

Includes every file the saved glTF refers to that could not be found. Owned by the document; cleared at the start of each save.

Public property SavedFiles: TStringList read FSavedFiles;

What the last save did with each separate buffer and image file.

One line per file, for example "textures/brick.png: copied from D:\found\brick.png", "...: written from embedded data" or "...: already in place". Empty after a save to a stream. Owned by the document; cleared at the start of each save.

Public property SaveComplete: Boolean read FSaveComplete;

True when the last save is file-complete.

File-complete means every file the saved glTF refers to exists next to it, so it loads without missing files. False when a referenced file could not be found; SaveWarnings names it.
