Description

Loads and saves glTF 2.0 documents as .gltf JSON or .glb binary files.

TglTFDocument is the entry point. Loading reads a .gltf or .glb asset from a file, a stream, a string, bytes or an already parsed TJSONValue into a TglTF object tree. The format is detected from the content, not the file name. Buffer and image bytes are copied into the objects (TglTFBuffer.Data, TglTFImage.Data) from the GLB BIN chunk, data URIs or external files.

Saving writes .gltf or .glb, chosen by the file extension (or explicitly for streams). Everything written comes from the objects: the JSON from TglTF.SaveToJSON and the binary data from the Data properties. Nothing is copied from the file that was loaded. By default a GLB stores every image inside it, in the BIN chunk, and a glTF writes every image as a separate file next to it; with TglTFSaveOptions.ImageSaveMode set to ismPerImage, each image's Embed flag decides instead whether it goes into a buffer (GLB: the BIN chunk; glTF: a new base64 data-URI buffer) or into a separate file. Animations whose ExportOnSave is False are left out, together with the accessors, bufferViews and buffer bytes only they used, and so are images no mesh shows (see TglTFSaveOptions.LeaveOutUnusedImages).

A save to a file is made file-complete: every separate buffer and image file the saved glTF refers to is written or copied next to it, unless it is already there with the same bytes. Files that could not be found are reported in TglTFDocument.SaveWarnings and TglTFDocument.SaveComplete is False. 

Load:  file / stream / string / bytes --> TglTF objects + Data
Save:  TglTF objects + Data --> copy --> storage chosen per buffer / image --> output
       separate files: written next to the output (SavedFiles lists them)

None of the classes in this unit are thread-safe; use a document from one thread at a time.

Description

Types

TglTFFileFormat = (...);

The two glTF file formats.

Values
  • gffNone: No format: nothing is loaded, or the file name has no .gltf or .glb extension.
  • gffJSON: glTF JSON text, usually a .gltf file.
  • gffGLB: Binary glTF, a .glb file.
TglTFResourceMode = (...);

Where the data of a buffer goes when saving.

Applies to buffers only; images follow TglTFImageSaveMode. In a GLB, buffers[0] always goes into the BIN chunk whatever the mode.

Values
  • rmKeep: Keeps each buffer's kind: data URIs stay data URIs, external files stay external files, written next to the output.

    A buffer that was in a GLB BIN chunk becomes "<name>.bin" when saving .gltf.

  • rmEmbed: Embeds every buffer as a base64 data URI.
  • rmExternal: Writes every buffer as a file next to the output.
TglTFImageSaveMode = (...);

Where the images go when saving.

Values
  • ismByFormat: The format decides: a GLB stores every image inside it, in the BIN chunk; a glTF writes every image as a separate file next to it.

    The images' Embed flags are ignored. A glTF saved to a stream, which has no folder for files, still holds its images as data URIs.

  • ismPerImage: Each image's TglTFImage.Embed flag decides, in either format.
TglTFResourceKind = (...);

The two kinds of external file a glTF can refer to.

Values
  • rkBuffer: A buffer, an entry of TglTF.Buffers.
  • rkImage: An image, an entry of TglTF.Images.
TglTFProgressEvent = procedure(Sender: TObject; const AProgress: TglTFProgress) of object;

Event reporting progress, like TNotifyEvent with the progress added.

Called on the thread doing the work: when loading runs in a background thread, a handler that updates the user interface must pass the update to the main thread, for example with TThread.Queue. The handler must not change the document.

Parameters
Sender
The document or importer doing the work.
AProgress
How far it has got.
